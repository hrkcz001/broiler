## What was built

- **Settings window** — a real dialog created from an in-memory `DLGTEMPLATEEX`
  (`CreateDialogIndirectParamW`), `DS_SETFONT` with `MS Shell Dlg`, themed combo box, checkboxes and
  buttons, Tab order, `Escape` and the default button through `IsDialogMessageW`. The window decides
  nothing: it calls an `Action` and is then refreshed from the coordinator.
- **Flyout** — a modeless `WS_POPUP` tool window anchored to the icon, holding a standard themed
  `SysListView32` over an image list. The current profile is its own leading column with the text
  `Current` and a marker dot; selection and focus stay the control's own. Pending and failed
  operations go to a short status line, never into a profile name. `Escape` and click-away close it.
  No Settings button.
- **Artwork** — original coloured glyphs (sun, crescent, and the rest of the named set) drawn as
  anti-aliased RGBA, with an opaque badge plate for monitor index digits, replacing the monochrome
  symbols. Recognisable by silhouette as well as colour.
- **`tray.always_show_monitor_name`** — default `false`, exposed through `broiler settings get/set`
  and through the dialog checkbox. One controlled monitor with the preference off omits the name;
  several monitors always show index and name.

## Defects found and fixed inside this gate

1. The dialog template was written as `0xFFFF, 1` — signature first. The loader reads `dlgVer` first,
   so the words were taken as a standard template and `CreateDialogIndirectParamW` returned null with
   `GetLastError` 0. Verified with a throwaway probe program before touching the product.
2. Controls were created without `WS_CHILD`, so the dialog appeared with an empty body. A resource
   compiler adds that bit; a hand-built template must add it.
3. One physical click delivered three callback events; the flyout opened three times and would have
   applied a profile three times. Activation is now decided per encoding, with a regression test.
4. `Escape` in the flyout was delivered to the list view, so the popup's own window procedure never
   saw it. The message loop now dismisses the popup when the key belongs to one of its children.
5. An all-transparent image in the image list arrived as an opaque black square; rows without the
   marker now ask for `I_IMAGENONE` instead.
6. The marker dot was drawn with a hard edge and read as a square at 16 px; it is now coverage-blended,
   with a test that fails on a hard edge.

## Not established

These are untested, not passed:

- **Screen reader.** Narrator was not run. The current marker carries the text `Current` so the row has
  an accessible label, but the marker column itself was not heard.
- **High Contrast and dark mode.** Only the system light theme was observed. No dark-mode or
  high-contrast claim is made; the artwork uses fixed colours and the marker does not follow system
  colours.
- **Display scaling.** The machine runs a single DPI. Scaling is unit-tested through the metrics
  function only.
- **A second display.** One DDC-capable monitor is attached. The "several monitors" row of the name
  rule is covered by unit tests, not by a screenshot.
- **Explorer restart.** Not performed; it is disruptive and was not coordinated.
- ~~Slow worker~~ — now established, see the row below.
- **Shell tooltip.** The tooltip shown by the shell was observed earlier in the session
  (`Day, 100%`), but not on a scripted hover with the monitor-name preference on, so the tooltip's
  text under that preference is unproven. The heading uses the same label function and was captured.
