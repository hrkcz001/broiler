# Gate R2: read-only preserve reconciliation

Date: 2026-10-25. Work order: `docs/handoff-v2-2026-10-25.md`, gate R2; contract:
`docs/ux-contract-2026-10-25.md` section 1. Everything below came from a command or a test on this
machine; nothing is inherited.

## What was built

- `src/reconcile.rs` — the comparison, as a pure function over one evidence set and the loaded
  profiles. The expected native value is produced by `plan::plan` with the same metadata and the same
  rounding the apply path uses, so "the profile would be written as N" is compared with "the device
  reports N". There is no second conversion and no epsilon.
- `src/state.rs` — the only persisted fact reconciliation needs: per monitor, the profile id and the
  content fingerprint of the last *verified* application. Atomic write, missing file means empty
  history, unusable file means empty history plus a log line, and reading never writes.
- `Coordinator::reconcile` — reads each requested control exactly once per monitor through the single
  serialized transport, records the observations in the read cache the tooltip uses, classifies, logs
  the observation with its timestamp, and publishes the change through the one notification path.
- One snapshot per monitor, `Coordinator::current`, read by the tray icon, the tooltip, the flyout
  marker and `status`. `state_label` is a pure function of it. `profile.next` starts after the profile
  that snapshot reports, not after the first one.
- Provenance is kept apart: `matched` (reads agree, nothing written), `applied_verified` (this process
  wrote it and the readback matched), `custom`, `unknown`, `checking`. A direct write drops the claim
  and re-reads; a partial or timed-out write leaves `unknown` and forgets the history.

## Tests (306 passed, 0 failed)

`MSYS2_ARG_CONV_EXCL='*' cmd.exe /c build.bat test`

The reconciliation tests, by requirement:

| Requirement | Test |
| --- | --- |
| Percent and raw match exactly | `a_percent_profile_matches_the_native_value_the_planner_would_write`, `a_raw_profile_matches_only_the_exact_integer` |
| Nonzero range and the planner's rounding | `a_nonzero_range_is_mapped_with_the_planners_rounding` (20..=80; 1 % is 21, 22 is a mismatch) |
| Every requested field must agree | `every_requested_field_must_agree` |
| Partial reads are unknown, not custom | `an_unread_field_makes_a_candidate_unverified_rather_than_custom`, `an_unsupported_read_is_unknown_not_custom` |
| A temperature profile is not certified by brightness | `a_temperature_profile_is_never_certified_by_brightness_alone`, `an_unsupported_read_leaves_the_monitor_unknown_and_claims_no_profile` |
| Several matches: history, then registry order | `identical_candidates_are_decided_by_history_then_by_order` |
| Edited profile invalidates the stored fingerprint | `a_fingerprint_changes_when_a_value_changes_but_not_when_a_name_does`, `the_persisted_history_breaks_a_tie_and_a_failed_apply_drops_it` |
| No candidate is custom only with complete reads | `no_candidate_at_all_is_custom_only_with_complete_reads` |
| Pending state and zero writes | `nothing_is_decided_before_the_first_observation`, `an_observation_writes_nothing_and_reports_matched_not_applied` |
| Empty profile is not a vacuous match | `a_profile_without_hardware_fields_is_not_a_vacuous_match` |
| Disconnect drops the claim | `a_monitor_that_was_unplugged_loses_its_claim` |
| One snapshot for every surface | `the_tooltip_state_is_the_profile_display_name_and_not_its_id` (checking → applied → custom → matched through one coordinator) |
| Cycle starts after the observed winner | `a_cycle_starts_after_the_observed_profile_and_not_at_the_first_one` |
| Status refresh observes once; plain status does not read | `a_status_refresh_observes_once_and_an_ordinary_status_does_not_read_hardware` |

## Limits

- The live evidence is one monitor and two controls. Temperature, RGB gains, colour presets, volume and
  mute have no read path in this build, so a profile containing them can only ever classify as
  `unknown` here. That is the honest outcome, not a passing match, and it stays until R4 adds the
  temperature backend.
- Several matches were only constructed in tests: the real display had one user profile pair that
  differed, so the tie-break ran against a fake backend, not against hardware.
- `status` is the CLI surface observed live. The tray icon, tooltip and flyout read the same snapshot in
  code and in unit tests, but their on-screen appearance is R3's evidence, not this gate's.
- No reconnect or wake was exercised on real hardware; the disconnect path is covered by a fake
  transport.
